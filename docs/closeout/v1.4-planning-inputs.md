# Inputs for Registry Engineering Plan v1.4

**This is input to v1.4, not the plan, and not authorization.** Release, publication and production: HOLD. Tier 1: NOT STARTED. Status basis: [program-closeout-2026-10-26.md](program-closeout-2026-10-26.md).

## 1. Proposed minimum operational profile (from adopted decisions)

Scope stays the F1a allow-list family (allowed units, adapters, actions) plus the integer-second age families F4/F5 already implemented in the Registry, one tenant, one scope, Linux x86-64 CPython 3.11-3.13, Ed25519 synthetic or operator-supplied keys. Authority model as adopted in [EXT-S4-0](../decisions/2026-10-26-adr-ext-s4-0-integration-contract.md), TR-01 and `r08-v2` (+ Amendment 1): the Runtime owns durable activation state; the Registry only narrows; the Control Plane binds approval to the effective-policy digest. Anything wider is outside this profile.

## 2. Smallest demonstrable Registry-Control Plane-Runtime workflow

Registry produces a signed, verified selection and effective-policy identity (exists, #26/#33/#34) → Control Plane issues an approval bound to that digest (R6 exists, #84; claim-carried binding missing) → Runtime verifies the claim, durably activates it in one SQLite transaction and refuses a stale, withdrawn or replayed selection (nothing exists) → one allowed and one refused execution observed, then a restart that recovers state by replay.

## 5. Minimum independent qualification gates

An independent cryptographic reviewer for the Ed25519 adapter and canonical-base64 verifier path (lifts the SECURITY-HELD labels on #26/#34); an independent reviewer of the Runtime atomic guard and recovery path once built; one independent end-to-end run at exact pins (EXT-S6-2 equivalent); a named Tier 1 lead (GAP-G4-13). Copilot or AI review does not satisfy these.

## 6. Decisions that need the operator

Whether to authorize EXT-S4 and in what order; whether to designate a Tier 1 lead and reviewers; whether the demonstration may use synthetic keys only; whether Control Plane EXT-S3-1..3 stay in scope or are replaced by R6; CCTV vector licence confirmation; the Runtime owners' view on the E05 surrogate boundary (carried from S06); manifest pin approval remains none.

## 7. Explicitly deferred beyond the minimum profile

New rule families, shared ISS/OCS registry integration (COG-REG-SHARED-ADD-01), dynamic activation beyond the ADR, multi-tenant or multi-scope operation, other platforms or Python versions, deny-all or wider character representation in the contract, publication, production and release.
