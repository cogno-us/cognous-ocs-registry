## D-06: persisted effective-configuration binding

**Source facts (read, and verified by running where marked).** A governed decision persists only `binding.runtime_authority`, a free-form dict holding `catalogue_digest` (the final effective profile hash, runtime_authority.py:473) and `approval_commitment` (:236-251). The F4 scalars (`status_max_age_seconds`, `approval_max_age_seconds`), `ObservationPolicy` (it is only echoed into `ReconciliationResult` as evidence and never compared), identity/mandate ages and the declared family set with contract versions are bound nowhere. On execute and on pin export the whole stored binding dict is compared to the live one (bounded.py:1690-1693; authorization_pin_export.py:183-188), so a decision persisted under scalars/ObservationPolicy A executes after a restart under B whenever the profile is identical (characterised by `test_i04`). The activation ledger is in-process and lost on restart. `EffectivePolicySnapshot.identity_digest` includes `evaluated_at`, so it cannot serve as a persisted binding. (Verified by running: typed decision models ignore unknown members; a one-key-larger `runtime_authority` dict makes bindings unequal, so a legacy reader fails CLOSED on a new record.)

**Options.** A: document only (the three parameters stay BLOCKED; a decision survives a configuration change). B: a versioned, backward-compatible persisted effective-configuration binding. C: put the scalars into the approval preimage or the profile (strongest; changes `approval_commitment`, touches protected files, new reason vocabulary, largest migration cost).

**Recommendation: B, carried as `runtime_authority["effective_configuration"] = {version: "effective-configuration-binding/0.1", digest, members}`**, opt-in (default OFF, so the default path stays byte-identical), minted and checked in the non-protected `registry_governed_lifecycle.py` `_resolve` override. Preimage (domain `cognous.control-plane.effective-configuration-binding`): scope; host profile digest; effective profile digest; F4 scalars (live values even when the F4 family is not declared); ObservationPolicy with an explicit null when absent; the declared family list (slot, family id, contract version, schema revision, effective-policy digest). Excluded: `evaluated_at`, and by default selection id/epoch (an equal re-selection is accepted today). Refusal: the registered `authorization_binding_changed` (durable `EffectTimeRefusal`); no new durable reason code (that needs `runtime-authority-reasons/0.4` and a protected edit). Legacy records (key absent) execute under today's semantics ONLY below an explicit host `legacy_cutoff` index in the append-only decisions list; no default, no wildcard; absent past the cutoff, no cutoff, or unknown version means refuse. Existing approvals are untouched (the approval preimage does not change); legacy records stay distinguishable; the binding confers no authority and removes no negative evidence. Mixed fleets: a legacy writer after upgrade cannot be stopped by code, matching the existing "stop old writers" requirement.

**Honest limits.** The store is unsigned (tests rewrite persisted values), so this guards configuration drift, not a malicious store writer; there is no durable ratchet, so rolling back to a matching older configuration revives an old decision.

**This is NOT gate-neutral.** Execute and claim gates compare the whole dict, so it changes persisted content and the comparison set. REQUIRES Architect authorization and F3 requalification: the carriage choice (dict vs typed field vs durable floor row; the last two are schema-altering), the preimage member set, opt-in vs default-on, legacy cutoff vs durable floor, inversion of characterisation test `test_i04`, and per-family byte pins. **Not implemented.**

## D-07: freshness guarantee

**Reproduced (deterministic, no sleeping).** `tests/test_freshness_purpose_residual.py` (Control Plane branch `freshness-purpose-residual-regression`, 10 tests passing on unchanged source): with the anchor flag True and NO `policy_binding`, class bound 30 s, purpose observed 30 s before evaluation, dispatch stalled 29 s, the effect is dispatched with the purpose observation 59 s old (a 30 s stall also dispatches at 2x; 31 s is refused); the accepted cached-purpose snapshot behaves the same. Contrast: with a `PolicyBinding` the same stall is refused for both. Controls: grant status, identity and mandate ARE anchored. The purpose observation is anchored only when the flag is True AND a `PolicyBinding` is present (runtime_authority.py:404); `age_ceilings` is irrelevant. Outage extensions cannot defeat a narrowed ceiling for anchored inputs (class-age composition caps base + extension), but the residual exists regardless, up to about 2x (base + extension).

**Options (smallest source-backed change first).**
- **A: protected-evaluator correction.** Make the block at runtime_authority.py:404-413 unconditional (drop `if binding is not None:`; the collector already limits it to anchor-flag checks; bounded.py needs no edit). A scratch prototype closes the window: the three residual tests fail as intended, contrast/control pass; across 7 related test files 304 passed, 2 skipped, 1 failed (the pinned legacy test, tests/test_policy_binding_approval_generation.py:586, to be inverted). Pure `min` added to the deadline: no new authority, no commitment change, no persisted-schema change, no new reason code; strictly more restrictive. **Protected-evaluator edit: REQUIRES separate explicit Architect authorization and F3 requalification.**
- **B: compatible policy_binding integration.** Mechanically safe (every composer passes `policy_binding` through unchanged; lift the refusal only for the anchor family), no protected edit, but not a Registry-side fix: it forces the host onto `approval-commitment/0.2` and a REAL generation/activation source (EXT-S4 anti-rollback is not implemented), invalidates existing approvals, and reopens the undecided generation semantics. Inventing placeholder binding values would be a fabricated authority claim. Acceptable only as an explicit host precondition with an Architect ruling.
- **C: alternatives without a protected change.** None proves equivalent enforcement: a gate-side purpose-age re-check lacks the monotonic/wall-clock-step guards, writes no `check_expired_before_dispatch` rows and covers only governed workflows; a refusal rule is a total availability loss; clamping the base changes the class-age family's meaning and commitment. Not recommended.

**Recommendation: A.** If neither A nor B is authorized there is no safe option: the anchor family stays BLOCKED, or (D-C4) the residual is recorded as an accepted limit of up to 2x the ceiling and the parameter is NOT described as resolved. Setting the flag alone does not satisfy the invariant. **Not implemented.**
