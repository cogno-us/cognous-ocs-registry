# Defect record DEF-OBS-TOL-OVERFLOW-1: extreme `ObservationPolicy.clock_tolerance_seconds` raises OverflowError

Status: recorded, NOT fixed, NOT in the authorized migration scope. Isolated as a separate source-backed defect needing its own Architect decision (directive section 7). Non-authorizing.

Source (Control Plane main `b7eb11aaeed9c766ecaae7d22955093f7f7cd1aa`, protected `src/agent_control_plane/bounded.py`): `_reconcile_observation` computes `future_limit = reference + timedelta(seconds=policy.clock_tolerance_seconds)` (`bounded.py` around :1922). `ObservationPolicy.clock_tolerance_seconds` is `int = Field(default=5, ge=0)` with no upper bound. Probe evidence (annex C, `c_probe_obs_reconcile.py`): tolerance `10**12` and `10**30` make `reconcile()` raise `OverflowError` out of `_reconcile_observation`; `2**31-1` and `2**31` do not; a very large `max_age_seconds` never overflows (float comparison).

Effect class: availability / robustness of the post-effect reconciliation path. The exception propagates instead of producing a `ReconciliationResult` with a hold reason; no authorization is granted by it (an exception cannot authorize). It is reachable only through host configuration of an unbounded field. It is not introduced by the Registry, which can only lower the value, and the r08-v8 tolerance family refuses any host value outside its structural range rather than composing with it.

Decision NOT taken here: whether to add an upper bound or to saturate the arithmetic. Either changes protected `bounded.py` and the supported host domain ("no invented upper limit"). Options for the Architect: (1) accept and document as a host-configuration fragility; (2) a bounded.py correction converting the overflow into a deterministic hold (for example `observation_policy_invalid`, which is a new reason requiring a vocabulary decision) with F3; (3) a supported ceiling, which is a policy decision. No change is made under this directive. Reproduction retained in the final-three evidence.
