## Cross-cutting facts that shape the oracle work

1. **One token rule for five sets.** `v2_f1ab._entry_ok(field, item)` ignores `field`; nothing would notice a per-field divergence (M1-E-01).
2. **Three validators for the same lists** (`v2_f1ab._list_ok`, `v2_policy_identity.validate_effective_payload`, caller `normalize_caller`) plus `LocalExecutionPolicy.__post_init__`, which accepts any non-empty string including `*` and empty/unbounded sets (M1-E-02, M1-E-31, M1-F-01).
3. **Registry narrows by intersection; Runtime checks subset.** Compose time yields caller ∩ record; effect time enforces executor-sets ⊆ record payload inside the same atomic transaction (`policy_not_subset:<field>`, REFUSE `policy_identity_mismatch`). Nothing proves the two agree end to end for the two sets (M1-F-06, HIGH).
4. **The scope and the payload sets are unrelated in code, tests and contract text** (scope.institution / scope.authority_domain vs allowed_institutions / allowed_authority_domains): the contract never says independence or containment (M1-E-12, HIGH). This is a specification question, not an oracle (see PD-1).
5. **Amendment 3 is prose with text-pin tests only in the Registry; Amendment 4 is a DRAFT.** No executable Registry-side oracle for effect-time containment exists (M1-E-21, HIGH).
6. **Deny-all** is an explicit `[]`; an absent key is `field_missing`. Composer deny-all covers all five keys (32 empty combinations); decision-level and durable-level deny-all for the two sets is untested (M1-E-10, M1-F-07, HIGH).
7. **Reason compatibility:** at decision level every record fault collapses to `composition_record_invalid`; the effect-time reasons `store_unknown` (HOLD), `policy_identity_mismatch` (REFUSE) and `verifier_unavailable[policy_sets_*]` are pinned for containment, but `policy_digest_unavailable`, `policy_sets_malformed`, `binding_validator_unavailable` and `registry_unavailable_for_policy_digest` are not (M1-F-17).
8. **Stale state and recovery:** revocation, withdrawal, expiry, rollback and restart tests run on the single default record and assert nothing about the two sets; `reconcile_claim_exact` never reads the selection store; no record-level revocation exists (M1-F-20..23).
