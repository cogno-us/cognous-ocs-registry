## True vs false and the arithmetic
- False: deadline D0 = `opened + bound`. A status observed `bound` seconds before opening passes the evaluation check (age <= bound) and may be dispatched until D0, i.e. age at dispatch up to `2*bound` (pinned by tests/test_freshness.py:805-824).
- True: D = min(D0, min_i(observed_i + bound_i)) over every input judged by `_fresh`; applied only `if earliest < deadline` (bounded.py ~2133), and again as `min()` at the gate (bounded.py:1416-1420). Pure `min`, so D <= D0 always: true is strictly more restrictive in these paths (it can only withdraw a licence earlier, `check_expired_before_dispatch`). No path was found where True is looser. Note `bound_i` includes the F4 scalars (status/approval/identity/mandate ages), so the anchor also enforces the Registry-narrowed F4 ages at dispatch.

## Can an extension or the anchor calculation defeat a Registry-narrowed ceiling?
- Extension: no, given the existing class-age composition (base+ext <= Registry value) plus anchor True, because the anchor uses the (extension-raised) bound actually used, which is <= ceiling. An extension also cannot be applied to an irreversible class.
- Anchor arithmetic: cannot widen (min only; no addition, no clock-skew credit).
- RESIDUAL GAP (counterexample, anchor True, no policy_binding): `grant status` / `_fresh` inputs are anchored, but the PURPOSE observation is judged once at evaluation (`age > cl.max_status_age_seconds`) and is added to the deadline collector only under `if binding is not None` (runtime_authority.py:405-415). Narrowed class bound 30, purpose observed 30 s before evaluation (accepted), dispatch stalled 29 s: purpose age at dispatch 59 s (about 2x the narrowed ceiling), with anchor True and ceiling-narrowed class age. Fixing this means editing protected `runtime_authority.py` or using `policy_binding` (which the families refuse). Same applies to the cached-purpose snapshot (bounded.py:2160-2175; anchored only in the binding branch). Hence the anchor flag alone does NOT meet "no extension or timestamp calculation may defeat a Registry-narrowed ceiling" for classes with a purpose binding.
