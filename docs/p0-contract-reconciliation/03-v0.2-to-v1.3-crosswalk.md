# 3. V0.2 → registry v1.2 / R08 / v1.3 crosswalk

Existing semantics side by side. Verdicts distinguish genuine incompatibility from naming or placement differences. Ledger ids in the last column. Sources: V0.2 = hub `docs/program-v0.2/**` (`s02/contracts/1.3-registry-r0.md`, `s04/2.1-registry-records.md`, `s05/2.3-*`, `s05/2.4-*`) and `tools/registry_records.py`, `tools/mandatory_checks.py` at `51c579a3`; Registry = `docs/plans/PROJECT_PLAN-v1.2.md`, `v1.3-DRAFT.md`, `docs/r08-preparation/*`, `docs/r08-s01-contract.md`, `registry_successor/` at `ce00520f`.

## Reading guide

- V0.2 `ocs-registry-record/0` is a **whole governance rule-set** (rule table, evaluators, reason map, epoch, predecessor). R08 `r08-v1` is a **per-family typed configuration record** (F1a payload) plus a **separate signed selection**. They carry different content, so there is no content collision. **Do not merge the schemas.**
- No R08 document cites V0.2 R0/2.1/2.3/2.4. Agreement on partitions, fail-closed behaviour, "no latest" and "no fallback" is convergent. Plan v1.3 §2 is the first registry document that names R0 and instructs: treat it as prior design, not as proof of frozen wire formats.
- What V0.2 actually adopted in this area: the three-partition direction, ADR-P01, ADR-P03. Everything else in R0/2.1/2.3/2.4 is proposed or candidate.

## Differences that are only naming or placement (no action beyond the adapter map)

`digest` ↔ `record_digest`; `predecessor` ↔ `supersedes`; `issuer` ↔ `provenance.authored_by`; epoch in record versus epoch in selection; hex prefix usage; code names. Two uses of "epoch" must be given distinct names in the P2 contract: record succession order versus the selected effective epoch.

## Adapter list (all naming/placement; no new policy language)

1. Name the registry repository's canonical form as a legacy profile identifier (ADR-P01 allows named legacy profiles), or give any future record version JCS before a pin is approved. Nothing is activated, so the cost is low.
2. Note that `/0` accepts only a subset of RFC 8785 yet uses the identifier `rfc8785-jcs`, which the ODES full profile also uses. Qualify the identifier at the first cross-component digest.
3. Field-name map between `ocs-registry-record/0` and `r08-v1`.
4. Bind the registry's own named profile digest in decision context rather than re-canonicalizing, if P4 requires cross-component binding.
