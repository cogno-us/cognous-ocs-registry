# 6. Ordered PR and sprint execution plan

Status: **final planning sequence, not authorized sprints.** G-0 and G-2 are closed (inventory merged; operator Option B, Route B only). No PR below may begin until the Architect issues a separate implementation authorization and builder handoff, and its own stop gate is recorded ([01](01-executive-implementation-proposal.md)). This table is the final bounded EXT PR sequence; `max_amount` has no task in it. Each PR is one bounded owner increment, ends in a draft PR, and is not merged automatically. PR identifiers use the prefix `EXT-` because the labels S1..S6 collide with the historical sprints S01..S06 of plan v1.1. "Maps to" names the field IDs of [03](03-field-extraction-register.md), scenario IDs from the existing catalog (referenced, not restated), or the governance contract/ledger/gap the task serves. Evidence wording for everything produced: "developer-tested, Copilot-reviewed where reviewed, not independently qualified". Nothing is merged on the strength of builder tests alone being called independent.

Stop-gate legend: **G-3** `EXT-S1-1` accepted, which records the exact source candidate (R10-F-03) and therefore gates every source edit in S1, S2 and S3 (test-only PRs that add no source may be prepared earlier against the candidate named in the ADR draft, and merge after G-3); **G-4** carriage ruled (claim-carried), with the integration detail recorded in `EXT-S4-0`; **G-5** closed by the rulings in [10](10-architect-rulings-and-repin.md); **G-6** independent lead designated (qualification is PREPARE-only until then).


**Execution cards.** Every EXT PR has an eight-element execution card (pin or pin gate; fields and contracts; permitted files; tests to preserve; new negative tests; required checks; qualification dependency; rollback or stop) in [11](11-ext-pr-execution-cards.md). The tables here stay the canonical sequence; the cards add the bounded preparatory `EXT-S1-0` (registry test CI, no scope change) and `EXT-S2-G` (required-checks confirmation, no code). The LD-02 outcome map is [`data/ld02-outcome-map.json`](data/ld02-outcome-map.json): all 46 `r08-v1` codes are mapped (completeness test) plus the v2-only `trust_snapshot_version_stale` and `selection_withdrawn`; policy on/off schema-readiness is in [04](04-component-ownership-and-adapter-matrix.md).

## Review and merge discipline

Bounded owner increments only; one substantive review per PR; reserve additional independent technical review for code affecting authority, policy activation, canonical state or external effects (S1-6, S1-7, S4-2, S4-3, S4-4). Copilot is the operator-designated code reviewer for these PRs (comment-only; cited as "Copilot-reviewed", never "qualified"); it is not evidence review or qualification. **Merging this plan (PR #22) authorizes no EXT PR and no automatic implementation.** Each EXT PR needs the Architect's separate implementation authorization and its own explicit merge authorization after independent review and green exact-head checks; plan v1.3 section 7 permits no auto-merge except separately authorized exact-head changes. A new issue is a V1 blocker only if it violates an approved scenario, a mandatory security boundary or an explicit gate; otherwise it is marked DEFERRED with owner and impact.
