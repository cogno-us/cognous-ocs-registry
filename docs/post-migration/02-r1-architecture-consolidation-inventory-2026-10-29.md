## 2. Findings

1. **Registry: the measured duplicate mass is historical and byte-frozen.** `v4/v5/v6` verify, selection and record are AST-identical to the `v3` copy after version-token normalization: 1,026 code lines (11.0% of the 9,345 code lines of `registry_successor/`; 19.5% excluding the data table). The decision files match 91-99%. All 77 non-doc `registry_*` files in the v8 frozen-baseline manifest still match their baseline bytes; frozen modules are barred from importing the engine (`tests/test_r08v8_frozen_baseline.py::test_no_frozen_module_imports_the_engine_a_v7_or_a_v8_module`). **Expected Registry production-line reduction under the plan's own constraints is approximately zero.** The consolidation the plan calls R2 already exists for new versions: per-version cost was 850/901/837/993 lines for r08-v3..v6 (mean 895) against 101 (v7) and 110 (v8) on the unified engine (`registry_successor/engine/`, 1,290 lines).
2. **Registry: the only unpinned accidental duplicates are about 34 lines** (REG-8 three-line `_refuse` helpers in files mostly frozen; REG-20 five functions in unpinned v8 tests). Recommendation: leave them (value below the cost of a reviewed change).
3. **Registry: repeated work per decision is small and deliberate** (8 digest recomputations and 10 timestamp parses per `verify_and_decide_v8`, about 984 microseconds in total on the worker's machine; the repeats are re-checks, not waste to remove).
4. **Control Plane: the Registry-governed layer is the only place with real accidental duplication.** The layer is 10 modules, 2,674 physical lines (1,838 code lines); it was already consolidated once (`registry_governed_lifecycle.py` holds the single decide/execute/commit-gate skeleton). Remaining accidental duplication (annex C): CP-1 Registry-call and verdict-shape preamble in six modules; CP-2 class-map narrowing tails; CP-3 four private strict-integer JSON parsers; CP-4 three identical 11-line blocks in `derive_policy`; CP-5..CP-9 smaller items. The estimated ceiling if everything were accepted is about 205 physical lines (7.7% of the layer; an estimate). The plan itself states that a reduction in LOC is not success.
5. **Deliberate redundancy to keep** (annex C CP-10..12): the four mandatory boundaries (construction, decision entry, execute entry, commit gate), the held-state double checks and the profile-digest and D-06 member recomputation at each boundary are security redundancy; removing or caching them removes a detector and is STOP-ARCHITECT.
6. **Constraints that shape any change:** `registry_f4_age_governance.py` and `registry_f5_class_age_governance.py` are SHA-256 byte-pinned by tests (editing them needs a deliberate re-pin); `test_z04` forbids `importlib`, `registry_successor` and `model_dump` in `registry_governed_lifecycle.py`; tests monkeypatch `_registry_modules` and `importlib.import_module`, so shared helpers must keep those seams.
7. **No unnecessary runtime dependency** (Registry core is standard-library only; the only third-party production import is `nacl`, lazy; Control Plane: one duplicated dev-requirement line, CP-8). Re-use of `strict_json.strict_loads` for CP-3 is NOT equivalent (it accepts finite floats) and is a recorded rejected alternative.
