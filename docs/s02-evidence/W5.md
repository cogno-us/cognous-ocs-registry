Notes on method and limits
- Risk tiers are my assignment from the task definition (Tier1 critical, Tier2 substantive, Tier3 routine); the Constitution text itself was not fetched/read, so tier assignments are provisional.
- Test evidence is by test name/body where I read it; where I only saw test names it says "(name only)".
- "Closed enumeration" = a literal/frozenset/tuple in code that the code compares against exactly.
- Code-wide vocabulary context: schemas/runtime_authority_reasons_0_1.json has 121 codes, 0_2 has 164 (counted by script); test_scan6_manifest_validator_gate.py::test_invalid_manifest_is_a_registered_reason shows `invalid_manifest` is in 0_2 and not in 0_1. The registry-of-codes itself lives in those schemas (outside my file set); the reason strings in my files that are emitted into decisions are only `invalid_manifest` (bounded.py:2611, caller of manifest_errors). Changing/removing a registered code is an external-commitment change (CA12/CA21) because version 0_1 vs 0_2 files are versioned artefacts.
- Schema correspondence (noted only, not analysed): validation.py issues/report -> schemas/validation_issue.schema.json, validation_report.schema.json; run/replay inputs -> run_record.schema.json, replay_bundle.schema.json; manifest_validation -> external action-manifest package (no local schema; Pydantic schema deliberately not ported, manifest_validation.py:6-10); decision_input_profile -> no matching schema file in schemas/ (vectors in tests/); reason_vocabulary -> runtime_authority_reasons_0_1/0_2.json; strict_json/time_instant -> none.
