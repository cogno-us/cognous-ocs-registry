# Trust limitations (consolidated, authoritative)

Non-authorizing, builder-side, not independently qualified. Release, publication and production HOLD. This is the one place to read what the S03 to S05 work does **not** establish. Each row links the original evidence; this page does not restate those documents. If this page and the original disagree, the original is the evidence and this page is wrong: report it.

- Plan: OCS-REG-PLAN v1.1 (blob `6ece90f6697320fd305d8eb8c1e3a7f2f1f428a2`). Constitution pin: https://github.com/cogno-us/cognous-engineering-constitution/blob/1c2e920f4e58e07a52e8e2408a506cf7dbc1292b/ENGINEERING_CONSTITUTION.md
- Authorization: [decisions/2026-10-24-s06-authorization.md](decisions/2026-10-24-s06-authorization.md).

## 1. What was and was not established

Established, for a bounded profile: a registry record contract for three allow-lists (S03), a consumer that can only narrow a caller's policy (S04), and differential evidence that, for representable values, the registry-backed policy behaves like the historical one and never widens it (S05, 1,728 + 168 grid pairs and the other frozen cases). Not established: anything about production, other fields, other rule families, other systems, or independent qualification.

## 2. Limitations

| # | Limitation | Meaning | Evidence |
|---|---|---|---|
| T1 | **Trusted-host threat model only** | Candidate record bytes and request inputs may be hostile. The approved manifest, its pin, the trusted checkout, the installed Runtime source and the verifier configuration are assumed outside the attacker's control. No claim against a compromised host administrator or root, a compromised interpreter, a malicious maintainer acting with authority, malicious build infrastructure, or anyone who controls the selection mechanism. | [S04 §2](s04-implementation.md); [decision P1](decisions/2026-10-24-s04-preconditions-and-authorization.md) |
| T2 | **S03 gives integrity, not authentication** | A record changed and re-digested still validates (case L1, S05 LIM-2). The S03 validator alone cannot say who approved a record. | [S03 §3, §6](s03-contract.md) |
| T3 | **Independent authority for record selection** | A record cannot authorize itself, and a manifest and record merged in one PR are not thereby authorized. Authority comes from a separately attributable operator or delegate decision. No such selection has been made. | [decision P2](decisions/2026-10-24-s04-preconditions-and-authorization.md) |
| T4 | **Manifest pin custody** | The pin is the SHA-256 of the exact manifest bytes, supplied only through trusted invocation (`TrustConfig`), never read from the record, manifest or repository. Whoever holds the pin holds the trust decision. The S05 harness plays operator for synthetic pins; only one case (R09) tests substitution against an unchanged pin. The API shape (PIN-3) is a signature check, not proof that no derivation path exists. | [S04 §2, §5](s04-implementation.md); [S05 report](s05-equivalence-report.md) |
| T5 | **Source-file verification, not loaded-code verification** | The consumer hashes the installed evaluator file on disk. It does not verify the code object loaded in a running process. A replaced in-process `check` is not detected (S05 LIM-1). | [S04 §8](s04-implementation.md); [S05 report](s05-equivalence-report.md) |
| T6 | **`record_source` is unverified provenance** | The manifest's repository, commit and path are informational. The consumer has no git access and does not check them (S05 LIM-3). The fixture value is a placeholder. | [S04 §3, §5](s04-implementation.md) |
| T7 | **Optional-overlay refusal semantics** | A refusal means "overlay not applied", never "denied", and the caller's own policy stays in force, which may be broader than a record's author intended (for example a refused empty-list record). If registry participation is ever mandatory, refusal must fail closed; that is a different, unauthorized profile. | [S04 §1](s04-implementation.md); [S06 A](s06-representation-and-e05.md) |
| T8 | **No approved activation pin** | The committed candidate manifest digest `sha256:948ab4f40bb0acf211124db42df2eb5908627e95d84b0019fade2f0b726c2791` is a candidate only. No pin is approved for use. Approving one is a separate operator decision. | [S04 §5](s04-implementation.md) |
| T9 | **Runtime integration is inactive** | Nothing calls the consumer. `LocalExecutionPolicy`, the executor and `baseline/` are unchanged. No record store, discovery, activation, expiry, tenant scoping, signing, key management or administration exists. | [S04 §8](s04-implementation.md) |
| T10 | **Review is not qualification** | The builder wrote the code, the oracle and the harnesses. GitHub Copilot (`copilot-pull-request-reviewer[bot]`) reviewed each PR diff on the exact head under an operator exception; that is technical code review, not independent qualification, certification, release acceptance or production authorization. The oracle is frozen and imports nothing under test, but it is still builder-authored. | [S05 decision](decisions/2026-10-24-s05-authorization.md); [S05 report](s05-equivalence-report.md) |
| T11 | **Untested production and cross-system behavior** | Not tested: other `LocalExecutionPolicy` fields, larger value universes than 2 and 3 values per field, concurrency, real adapters or destinations (the destination is synthetic SQLite), the Control Plane, other repositories, other Python versions than CPython 3.13.17 in the recorded runs, and any deployment. | [S05 report](s05-equivalence-report.md); [source-provenance.md](source-provenance.md) |
| T12 | **Representation limits are real** | Values the historical constructor accepts but S03 refuses (E01–E19) have no registry representation. The lone-surrogate class (E05) has three behavioral SKIPs: no equivalence is shown for it. | [S06 A and B](s06-representation-and-e05.md) |
| T13 | **Unresolved classifications stay unresolved** | The 32 unresolved S02 classifications and the relationship between the `60` and `300` freshness values are carried forward, not resolved. S02 itself is a bounded, AI-worker-classified, non-exhaustive inventory. | [S02 inventory §5, §7](s02-inventory.md) |
| T14 | **Baseline caveats** | The baseline is the operator-selected `g8-r10` review tuple, not an adopted release. The imported file self-declares a Control Plane commit that differs from the lock's. Its own constructor validation, check order beyond one pair and the unreachable one-effect branch have limited S01 test coverage. | [source-provenance.md](source-provenance.md); [sprint-status](sprint-status.md) |

## 3. Claims this repository does not make

Production readiness; independent certification or formal qualification; universal equivalence; protection against the excluded attackers in T1; integration with the OCS Control Plane or Runtime; completeness of the S02 inventory.
